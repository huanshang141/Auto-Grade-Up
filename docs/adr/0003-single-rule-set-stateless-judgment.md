# 强化判定采用单一规则集与无状态求值

- 状态：accepted（2026-08-29）

开始强化与继续强化共用同一棵条件树：列表初扫时判定是否值得强化，之后每个强化回合结束后重新读取属性、用同一棵树判定是否继续。决策机构的每次求值只依赖当次输入——圣遗物当前属性加「剩余强化次数」（从当前等级到满级还会发生的词条变动次数）——不保存任何跨回合、跨圣遗物的历史状态。剩余强化次数是唯一区分强化阶段的字段，让同一棵树能表达「成长早期给机会、接近满级要达标」这类随阶段变化的门槛。

这一语义天然覆盖重复扫到的情况：滚动一屏后上屏卡片可能残留，同一件圣遗物在一次运行中会被再次读取与判定，此时不做任何「已处理」去重——它若已被强化，等级与副词条的变化自然反映在判定输入里，判定结果本身就是「是否还需要继续强化」的答案；已满级的圣遗物则被筛选条件的等级上限排除。判定因此永远可解释、可重放：运行报告里的求值过程记录就是每个决策的完整依据。

## Considered Options

- 分阶段规则集（开始与继续各一棵树，或每个词条变动点各一套阈值）—— 拒绝：规则数量随阶段成倍增长，编辑与维护成本高，阶段之间的一致性还要人工保证。
- 带历史状态的判定（记录过往回合的决策，依据历史决定后续）—— 拒绝：历史状态让决策难以解释与重放，「止损的圣遗物再次被扫到」还需要额外的清理逻辑。
- 单一规则集 + 剩余强化次数 + 无状态求值 —— 采纳。
