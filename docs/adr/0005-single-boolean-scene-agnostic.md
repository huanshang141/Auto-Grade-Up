# 决策机构输出单一布尔值，场景分支归执行机构

- 状态：accepted（2026-08-29）

观测机构在两个界面采集圣遗物属性：圣遗物列表页右栏预览与强化页右侧区域。两个观测点的目的相同——获取词条与属性，产出同一种数据模型（spec §3），差异只在识别区域与文字格式；列表页读数同时服务筛选条件与强化判定，强化页读数只服务判定。决策机构对场景完全无感知：开始强化与继续强化是同一个问题在两个时机的两次求值（同一棵条件树，ADR-0003），输出单一的「是否强化」布尔值。「布尔值 + 当前界面」由执行机构映射为四种操作——列表页通过则进入强化页并强化一次、不通过则跳到下一候选；强化页通过则再强化一次、不通过则返回列表后移动到下一候选。界面知识由执行机构持有，因为导航本身由它执行。强化页读不到的字段（星级、套装名、锁定）由控制层沿用列表初扫读数——这些字段在单件强化过程中不可能变化。

## Considered Options

- 决策机构输出带场景的指令对象（如「进入强化页并强化」「返回并移动到下一候选」）—— 拒绝：决策机构被迫感知界面与流程，无状态判定（ADR-0003）被破坏，规则语义与界面操作耦合。
- 把规则求值下沉到执行机构自行推断 —— 拒绝：判定语义散落，运行报告失去统一的求值过程记录（trace）来源。
- 观测输出统一数据模型 + 决策输出单一布尔 + 执行机构按界面分支 —— 采纳。
