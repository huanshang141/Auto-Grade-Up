# 词条数值条件的判定口径是乐观可达值（强化剪枝）

- 状态：accepted（2026-09-06）

需求方澄清（2026-09-06 拷问）：词条数值条件的本意是「最终可达」——`sub.crit_rate >= 15` 指的是将来强化能达到 15 时才执行强化，词条存在是前提；若把剩余强化次数全部投入该词条仍达不到要求，则提前终止（强化剪枝）。M1 的决策机构实现按「当前值达标」求值，与该本意存在偏差：尚未达标但可达的圣遗物会被立即止损，「强化到达标」的目标无从谈起。修正方式为把词条数值条件的判定口径定为乐观可达值（定义见 CONTEXT.md）：由决策机构按圣遗物当前值（待激活词条用预览值）、剩余强化次数与游戏档案中的单次强化成长上限自动推导，不硬编码游戏数值（ADR-0004）；判定不通过即止损，并入合并单布尔（ADR-0005），判定无状态的原则不变（ADR-0003）。词条字段运算符的适用边界（乐观方向只对增长型条件成立）随 M2.5 规则文件格式修订一并明确。

## Considered Options

- 新增显式目标字段命名空间（如 `goal.sub.crit_rate`），当前值与可达值两种口径并存 —— 拒绝：需求方澄清词条条件的本意即可达语义，双口径徒增学习成本与写错规则的风险。
- 维持当前值口径、把剪枝做成独立的辅助判定层 —— 拒绝：当前值口径下目标型规则会在初扫立即止损，剪枝无从发挥；同一条件两处求值也增加解释成本。
- 词条数值条件直接采用乐观可达值口径，决策机构按游戏档案推导 —— 采纳。

## 影响

- 决策机构求值实现（`agent/rule_lambda/evaluate.py`）与游戏档案格式（单次强化成长上限表）随 M2.5 修订。
- 设计文档 §4 的规则示例语义描述与字段表口径同步修订。
- 求值过程记录（trace）记录乐观可达值及其推导依据，保证剪枝决策可解释。
- 观测侧待激活行从「整行丢弃」修订为「入模（带待激活状态，预览数值作为推导输入）」（2026-09-06，CONTEXT.md「待激活行」条同步）。

依据：2026-09-06 与需求方拷问答复（词条条件即最终可达语义，剩余次数全部投入仍不足时提前终止）；`reference/pic/` L1 截图（待激活行可见且带预览数值）。
