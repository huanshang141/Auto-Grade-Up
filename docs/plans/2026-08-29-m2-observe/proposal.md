# M2 提案：观测机构（observe）

## 背景与目标

M1 已交付决策机构（rule_lambda）：规则文件校验与无状态求值验收完毕。观测机构是它的上游——从游戏截图读出圣遗物属性。M2 目标（见 `concept.md` §1）：**不连真机，证明「一张截图进来，一个正确的圣遗物属性结构出来」**，识别质量与解析正确性都离线验证；对应 spec §14 的 M2 验收「截图样本回放，字段解析断言全部通过」。

架构基调（2026-08-29 定案，经 MaaFramework 能力研究）：图像识别全部走框架流水线（OCR / TemplateMatch 节点，模型取资源包 `model/ocr/` 的 PP-OCRv6）；Python 自建逻辑只做「文字之后」的处理。原则：**「图像变成文字和框」全在框架，「文字和框变成结构化属性」全在自建**。职责分界表见 `concept.md` §4，是本计划的上游约束。

## 范围（四项交付物 + 两层测试）

1. **解析核心** `agent/observe.py`（maa-free）：识别结果集 + 游戏档案 + 字段对照文档 → ReadResult（含两个读取器：列表页、强化页）。
2. **流水线识别节点定义** `assets/resource/pipeline/genshin/observation.json`：两界面全部区域，720 短边坐标从夹具标定。
3. **字段对照文档** `assets/resource/genshin/textmap/zh_cn.json` 数据文件 + 加载校验器 `agent/textmap.py`。
4. **测试夹具**：截图（统一 1280×720、涂黑 UID）+ 识别结果转储 + 补拍清单（下表）。

两层测试：转储单元测试（maa-free）+ 离线全链路测试（maa 绑定为开发依赖，跑与运行时完全相同的框架识别）。

## 非目标

ReadArtifact 注册与真机截图（M3）；界面导航、点击、放入狗粮（M3/M4）；语言锚点与放入设置自检（M3）；运行报告（M4）；其他游戏的区域标定（各游戏立项时）。
