# M2.5：强化剪枝与强化次数体系

- 日期：2026-09-06
- 状态：计划经两轮拷问定案（见同目录 discussion.md），待执行
- 依据：ADR-0006（词条数值条件的可达性语义）、ADR-0007（双通道识别）、主 spec §14 M2.5 行

## 为什么

词条数值条件的需求本意是「最终可达」（`sub.crit_rate >= 15` = 将来强化能达到 15 才执行），M1 决策机构按「当前值达标」求值，目标型规则会在初扫立即止损。同时需求方需要以词条强化次数（roll count）为条件的规则体系，用于强化剪枝与「按次数设规则」两套用法。

## 范围

- 游戏档案扩充「单次强化成长上限表」（4/5 星 × 属性代号）。
- 词条值对象扩展：强化次数（可空）与待激活标记入模。
- 决策机构：求值语义修正（词条条件取乐观可达值）、次数规则体系（独立顶层键 `roll_rule`）、运算符白名单收紧、规则文件格式修订与 JSON Schema 导出同步。
- 观测机构：待激活行入模、带圈数字解析、放大 OCR 与模板对比双通道交叉。
- 契约正本（四份 specs）与主设计文档同步修订。

## 不做

- 4 星圣遗物的解锁边角（暂不支持 4 星，M3 补样后再定）。
- CustomRecognition 真机接线（M3）、模板素材 ②④⑤ 的补拍（需求方按规格提供，到位后补验证）。
- 主词条成长曲线表（主词条条件维持当前值口径）。

## 影响

- 消费方：M3 执行机构（求值接口新增可选参数）、M4 报告（trace 形状变化）、M5 编辑器（规则格式与 Schema）。
- 破坏性：`Judgment.trace` 顶层形状变化、规则文件新增可选键、词条值对象新增字段——均有契约工作副本（specs/）在落定时折叠正本。
